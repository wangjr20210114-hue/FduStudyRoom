# 预约开始前15分钟发提醒

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s030sc01"></a>

## 场景一

### 场景概述

预约开始前15分钟，系统生成一份提前提醒。示例中09:00开始，08:45到点后，收件箱能看到包含教室、座位和时间的邮件。

### 操作步骤与预期结果

1. 预约09:00开始，已配置可观察的测试邮件服务和收件邮箱。
2. 08:44:59运行提醒处理，没有提前提醒。
3. 08:45:00再次处理，系统生成一份对应提前提醒。
4. 打开测试收件箱，可看到教室、座位、时间，并能对应到原业务事件。

<details>
<summary>场景编号与精确规则补充（S030.SC01）</summary>

- 场景名称：没到提醒时间不发，到点后能在测试邮箱看到
- 场景编号：S030.SC01

**对应的业务要求**

- M1-05.AC1：在开始前15分钟触发
- M1-05.AC3：发送真实邮件需要邮件服务，测试时用能实际查看的测试收件箱

**精确条件**

- 预约09:00开始、收件邮箱已配置测试SMTP

**精确动作**

- 将时钟从08:44:59推进08:45:00并执行调度

**结果与约束**

- 前者无提醒；后者创建一次提前提醒，测试邮箱可见教室/座位/时间；业务事件ID可追踪

</details>

<a id="s030sc02"></a>

## 场景二

### 场景概述

预约已经取消就不再发提前提醒；已经生成过的同一提醒，即使反复处理也不多建一份通知。

### 操作步骤与预期结果

1. 一笔预约已取消，另一笔已触发过提前提醒。
2. 系统对两笔预约重复执行提醒处理。
3. 已取消的预约不发送，已处理事件不增加新的逻辑通知。
4. 只有实际收件情况才能证明邮件到达，不能只凭日志说已送达。

<details>
<summary>场景编号与精确规则补充（S030.SC02）</summary>

- 场景名称：已取消的不发，已经处理过的不重复生成
- 场景编号：S030.SC02

**对应的业务要求**

- M1-05.AC2：已取消的不提醒，任务重试不多建通知

**精确条件**

- 一个预约已取消，另一个已触发提前提醒

**精确动作**

- 重复执行两个预约的调度

**结果与约束**

- 已取消不发；已触发事件不多建逻辑通知；不能只看日志就声称邮件送达

</details>

<a id="s030sc03"></a>

## 场景三

### 场景概述

离开始不足15分钟才创建预约，系统补一次提前提醒；邮件可能已发出但未确认时，投递详情如实显示待核实。

### 操作步骤与预期结果

1. 用户在08:50创建一笔09:00开始的预约。
2. 系统执行到期处理，补生成一份提前提醒。
3. 另一次邮件发送可能被外部接收但确认丢失，用户查看投递详情时看到待核实。
4. 该次结果不能标为已发送，也不宣称外部邮件严格只会收到一次。

<details>
<summary>场景编号与精确规则补充（S030.SC03）</summary>

- 场景名称：临近开始才预约要补提醒，邮件结果不明要如实显示
- 场景编号：S030.SC03

**对应的业务要求**

- M1-05.AC1：在开始前15分钟触发
- M1-05.AC3：发送真实邮件需要邮件服务，测试时用能实际查看的测试收件箱

**精确条件**

- 预约于08:50创建且09:00开始；另一次SMTP确认丢失

**精确动作**

- 执行到期任务并查看投递详情

**结果与约束**

- 08:50补一次提前提醒；未知外部发送结果显示待核实而非SENT，不承诺SMTP恰好一次

</details>
