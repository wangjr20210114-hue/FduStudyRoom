# 维修时停用整间教室，恢复时逐项检查原因

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s019sc01"></a>

## 场景一

### 场景概述

R101开始受维修单W1限制后，教室内所有座位都不能新预约，不只停用故障所在的那个座位。

### 操作步骤与预期结果

1. R101的A01和A02原本可用。
2. 系统按W1给R101添加维修限制。
3. 用户查询并尝试占用A01、A02，两者都不可新预约。

<details>
<summary>场景编号与精确规则补充（S019.SC01）</summary>

- 场景名称：教室进入维修后，里面所有座位都不能新预约
- 场景编号：S019.SC01

**对应的业务要求**

- RES-05.AC1：教室维修中，里面所有座位都不能新预约

**精确条件**

- R101两座可用

**精确动作**

- 以工单W1添加维修限制后查询全室

**结果与约束**

- A01/A02均不能新占用；不是只下架被报修座位

</details>

<a id="s019sc02"></a>

## 场景二

### 场景概述

同一教室有多种限制时，解除W1只移除W1的影响，其他维修单、管理员停用和整室占用仍然生效。

### 操作步骤与预期结果

1. R101同时受W1、W2限制，并存在管理员停用或整室占用。
2. 系统只解除W1对应的维修限制。
3. 用户查询教室，W2及其他有效限制仍保留，座位不会统一恢复可用。

<details>
<summary>场景编号与精确规则补充（S019.SC02）</summary>

- 场景名称：处理完一张维修单，不会顺便解除其他限制
- 场景编号：S019.SC02

**对应的业务要求**

- RES-05.AC2：验收后只解除当前维修单的限制，其他维修、停用或整室占用仍有效

**精确条件**

- W1、W2均限制R101，另有管理员停用/整室占用

**精确动作**

- 只解除W1，再检查W2、停用及整室条件

**结果与约束**

- W1限制解除；其他来源保留，座位仍受剩余条件约束，不自动全部恢复

</details>

<a id="s019sc03"></a>

## 场景三

### 场景概述

维修单的旧恢复通知晚到时，不能覆盖较新的维修状态；同一通知重复处理也不能改变限制数量。

### 操作步骤与预期结果

1. W1当前第2版仍在维修，旧的第1版恢复通知随后到达。
2. 系统处理旧恢复通知，再处理第2版维修通知的重复发送。
3. 查询教室时仍受新维修状态限制，旧通知不能恢复开放，重复处理不多建或误删限制。

<details>
<summary>场景编号与精确规则补充（S019.SC03）</summary>

- 场景名称：过时的恢复通知，不能把仍在维修的教室开放
- 场景编号：S019.SC03

**对应的业务要求**

- RES-05.AC3：重复消息和晚到的旧消息不能错误恢复座位

**精确条件**

- W1版本2仍处于维修，收到版本1的解除和版本2的重复添加

**精确动作**

- 依次处理乱序消息并查询限制

**结果与约束**

- 旧解除不能覆盖新维修状态；重复处理幂等，限制数量和有效性不被破坏

</details>

<a id="s019sc04"></a>

## 场景四

### 场景概述

教室维修期间，管理员新增或启用座位后，这些座位仍跟随整间教室处于不可预约状态。

### 操作步骤与预期结果

1. R101容量4，有A01、A02及停用A03，A04尚未添加，W1正限制整间教室。
2. 管理员新增A04，并启用A03。
3. 用户查询并尝试占用两座的09:00—10:00，系统都提示维修不可用。
4. 启用座位不会解除W1的维修限制。

<details>
<summary>场景编号与精确规则补充（S019.SC04）</summary>

- 场景名称：维修中新增或启用的座位，也仍然不能预约
- 场景编号：S019.SC04

**对应的业务要求**

- RES-05.AC1：教室维修中，里面所有座位都不能新预约
- RES-05.AC2：验收后只解除当前维修单的限制，其他维修、停用或整室占用仍有效

**精确条件**

- R101容量4，现有A01/A02及停用A03，处于W1维修限制；A04尚不存在

**精确动作**

- 管理员新增A04并启用A03，再查询及申请两座的T占用

**结果与约束**

- 新旧座位均因房间维修限制不可预约；管理员启用座位不等于解除W1限制

</details>
