# 查看站内消息，避免重复通知和过时提醒

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s062sc01"></a>

## 场景一

### 场景概述

用户在消息页面只能看本人消息。重复标已读不产生新记录，切换中英文后消息模板和状态有对应文字。

### 操作步骤与预期结果

1. user1和user2各有站内消息，user1打开消息页面。
2. user1读取自己的消息并重复标为已读，系统仍只保留原消息及已读结果。
3. 尝试查询user2的消息，被拒绝。
4. 切换中文和英文，系统消息模板和状态按当前语言显示。

<details>
<summary>场景编号与精确规则补充（S062.SC01）</summary>

- 场景名称：只看自己的消息，重复标已读不多建记录
- 场景编号：S062.SC01

**对应的业务要求**

- SUP-01.AC1：每人只看自己的站内消息，重复已读不多建记录

**精确条件**

- user1/user2各有站内消息

**精确动作**

- user1读取并重复已读，再请求user2消息

**结果与约束**

- 只返回本人；重复已读不产生第二份记录；越权拒绝，消息系统模板/状态支持当前中英字典

</details>

## 场景二

### 场景概述

通知事件重复到达时，站内只生成一份消息和待投递任务。未配置邮件服务时不能显示邮件已送达。

### 操作步骤与预期结果

1. 业务反复发送相同事件N1，真实邮件服务尚未配置。
2. 系统接收事件，用户打开站内消息，可以查到一份对应通知。
3. 查看邮件待办，只建立一份待投递任务，不标送达。
4. 邮件服务缺失不妨碍站内通知这一独立功能使用。

<details>
<summary>场景编号与精确规则补充（S062.SC02）</summary>

- 场景名称：没配邮件服务时，站内有消息也不能说邮件已送达
- 场景编号：S062.SC02

**对应的业务要求**

- SUP-01.AC2：可确认失败的邮件支持重试，结果可见，不能虚称送达

**精确条件**

- 业务重复投递逻辑事件N1，真实SMTP尚未配置

**精确动作**

- 接收并查询通知/投递任务

**结果与约束**

- 只创建一份逻辑通知和待投递任务，站内可查；不显示邮件已送达；可继续业务独立开发

</details>

## 场景三

### 场景概述

预约取消后，尚未发送的提醒一起撤销；已经送达的历史保留，不把过去投递伪装成从未发生。

### 操作步骤与预期结果

1. 提前提醒仍等待发送，系统收到预约取消事件。
2. 处理取消后，再执行提醒任务。
3. 待发送提醒已撤销，不再投递邮件。
4. 已送达通知仍保留历史记录，不删除或改成从未发送。

<details>
<summary>场景编号与精确规则补充（S062.SC03）</summary>

- 场景名称：预约取消后，尚未发送的提醒也要取消
- 场景编号：S062.SC03

**对应的业务要求**

- SUP-01.AC1：每人只看自己的站内消息，重复已读不多建记录
- SUP-01.AC2：可确认失败的邮件支持重试，结果可见，不能虚称送达

**精确条件**

- 预约提前提醒任务尚PENDING，收到取消事件

**精确动作**

- 处理取消后再次执行调度

**结果与约束**

- 待发送提醒取消且不会邮件投递；已经送达的历史不删除，不伪装从未投递

</details>
