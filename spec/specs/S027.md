# 提交预约时检查整点、时长和实际占用结果

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s027sc01"></a>

## 场景一

### 场景概述

用户提交预约时，起止必须是整点，结束晚于开始，默认最多4小时；不符合的时段不能占座。

### 操作步骤与预期结果

1. 当前08:00，教室08:00—22:00开放，上限4小时，分别从空闲状态尝试以下请求。
2. 用户提交09:00—13:00，其他条件符合时可成功。
3. 用户分别提交09:30—10:30、09:00—14:00和10:00—09:00。
4. 系统分别因非整点、超过4小时或时长不为正而拒绝，不产生占用。

<details>
<summary>场景编号与精确规则补充（S027.SC01）</summary>

- 场景名称：预约必须从整点开始和结束，默认最多4小时
- 场景编号：S027.SC01

**对应的业务要求**

- M1-02.AC1：开始结束均为整点，结束晚于开始，默认最多4小时

**精确条件**

- now=08:00，默认最长4小时，教室开放08:00—22:00

**精确动作**

- 依次提交09:00—13:00、09:30—10:30、09:00—14:00和10:00—09:00

**结果与约束**

- 仅第一项在无占用时可成立；非整点、5小时、非正时长均拒绝且不占资源

</details>

## 场景二

### 场景概述

预约不能从已过去的时间开始，不能超出关门时间，也不能超过管理员刚设置的新上限。旧页面信息不会放宽后端规则。

### 操作步骤与预期结果

1. 当前08:01，管理员已把最长时长改为2小时。
2. 用户分别提交08:00开始、21:00—23:00和09:00—12:00的预约。
3. 系统全部拒绝，不占用资源。
4. 即使旧页面仍显示最多4小时，后端也按当前2小时上限检查。

<details>
<summary>场景编号与精确规则补充（S027.SC02）</summary>

- 场景名称：已经过去、超过关门时间或超过新上限的预约不能提交
- 场景编号：S027.SC02

**对应的业务要求**

- M1-02.AC2：新设置实际生效，不能预约过去或超出开放时间的时段

**精确条件**

- now=08:01，最长时长已改2小时

**精确动作**

- 分别提交08:00开始、21:00—23:00、09:00—12:00

**结果与约束**

- 全部拒绝；新参数用于新请求，不能因旧页面显示4小时放行

</details>

## 场景三

### 场景概述

两位用户同时预约同一座位，只有一人获得已确认记录，失败者不能留下成功预约。成功结果能与占用、通知和操作记录对应。

### 操作步骤与预期结果

1. user1和user2选择A01的同一时段。
2. 两人同时提交，查看各自预约结果。
3. 只有一人得到已确认预约，且对应一笔有效占用；另一人没有已确认记录。
4. 成功预约的通知和操作事件可追踪到同一笔业务。

<details>
<summary>场景编号与精确规则补充（S027.SC03）</summary>

- 场景名称：两个人同时点预约，不能都看到成功
- 场景编号：S027.SC03

**对应的业务要求**

- M1-02.AC3：实际同时提交的数据库测试中，同座同一时段只能一人成功

**精确条件**

- user1/user2同时申请A01的T

**精确动作**

- 并发通过真实预约接口创建

**结果与约束**

- 只有一个确认成功并对应一个有效占用；失败者不留已确认预约；成功记录/通知/审计各有可追踪事件

</details>
