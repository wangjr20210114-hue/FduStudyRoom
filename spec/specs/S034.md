# 网络中断或服务重启后，把预约结果查清楚

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s034sc01"></a>

## 场景一

### 场景概述

预约请求已被资源服务处理但回复丢失，服务恢复后会核对同一笔业务，查清前显示处理中，不再多下一单。

### 操作步骤与预期结果

1. 预约请求已到资源服务，确认回复丢失，预约服务随后意外退出。
2. 恢复后用户打开“我的预约”，系统按原业务编号核对。
3. 未确认时只显示处理中；查清后显示同一笔确认预约或明确冲突。
4. 系统不产生第二份座位占用。

<details>
<summary>场景编号与精确规则补充（S034.SC01）</summary>

- 场景名称：座位已订下但确认丢失，重启后不会再订一次
- 场景编号：S034.SC01

**对应的业务要求**

- M1-02.AC3：实际同时提交的数据库测试中，同座同一时段只能一人成功

**精确条件**

- 资源已接受预约命令，预约域尚未收到确认

**精确动作**

- 杀死预约进程后重启并按同业务ID对账

**结果与约束**

- 恢复为同一确认预约或明确冲突；处理中不展示已落实；不产生第二份占用

</details>

<a id="s034sc02"></a>

## 场景二

### 场景概述

取消遇到网络异常后，系统继续原来的释放任务，页面能看到失败和重试情况，其他业务的占用或维修限制不受影响。

### 操作步骤与预期结果

1. 一笔预约正在取消释放，网络暂时异常，同教室还有整室占用或其他维修限制。
2. 网络恢复后，用户查看取消进度，系统继续已保存的待办。
3. 只释放这笔预约，页面显示真实失败、重试和处理结果。
4. 不通过直接修改其他模块数据库修复，也不解除其他来源。

<details>
<summary>场景编号与精确规则补充（S034.SC02）</summary>

- 场景名称：取消重试只释放自己的预约
- 场景编号：S034.SC02

**对应的业务要求**

- M1-03.AC2：只释放这笔预约自己的占用，重复取消不影响别的业务

**精确条件**

- 预约待释放，同室存在M2或另一工单限制

**精确动作**

- 注入资源超时后恢复网络并重试

**结果与约束**

- 持久命令恢复执行且仅释放本预约；失败/重试在页面可见，不跨库直接修复

</details>

<a id="s034sc03"></a>

## 场景三

### 场景概述

预约已因签到超时取消后，先前占用的成功消息即使晚到，也不能让预约恢复成功，系统会补做本笔释放。

### 操作步骤与预期结果

1. 预约已经到截止并取消，原占用命令的成功确认此时才到。
2. 系统核对结果，并重复处理该确认。
3. 预约始终保持超时取消，必要时只补释放自己的占用。
4. 不复活预约，不多记违约，也不多发取消通知。

<details>
<summary>场景编号与精确规则补充（S034.SC03）</summary>

- 场景名称：已经因超时取消的预约，不会被迟到的成功消息恢复
- 场景编号：S034.SC03

**对应的业务要求**

- M1-07.AC1：取消预约、释放自己的占用、通知用户，并只记一次违约
- M1-07.AC2：服务重启后补处理到期任务，不重复记违约

**精确条件**

- 预约已在截止取消，但收到先前占用命令迟到成功响应

**精确动作**

- 执行对账及重复响应处理

**结果与约束**

- 保持截止取消，按同源补偿释放；不复活预约、不多记违约或多发取消事件

</details>
