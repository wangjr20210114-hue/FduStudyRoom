# 搜索座位并按地点、时间和插座筛选

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s026sc01"></a>

## 场景一

### 场景概述

用户在座位预约页面选择校区、日期、时段并勾选需要插座，搜索后只看到符合全部条件的座位。

### 操作步骤与预期结果

1. R101的A01和A02在09:00—10:00都空闲，只有A01有插座。
2. user1打开座位预约页面，选择邯郸校区、2030年6月3日和09:00—10:00，勾选“需要插座”。
3. 点击“搜索”，结果只显示R101的A01，并展示教室、座位编号和插座标记。
4. 提交给后端的条件与页面选择一致。

## 场景二

### 场景概述

用户搜索时，系统不把无院系资格、已有占用或维修中的座位列为可预约，直接提交也不能绕过检查。

### 操作步骤与预期结果

1. user2无CS资格，R102限定CS，R101在查询时段已有占用或维修。
2. user2打开座位预约页面，搜索该时段。
3. 结果不显示上述不可预约项，后端资源接口也检查相同限制。
4. 不能通过绕开页面直接下单取得不可用座位。

<details>
<summary>场景编号与精确规则补充（S026.SC02）</summary>

- 场景名称：不把无资格或正在占用、维修的座位列为可预约
- 场景编号：S026.SC02

**对应的业务要求**

- M1-01.AC2：只显示开放、有使用资格、没有占用或维修的座位

**精确条件**

- user2无CS资格，R102为CS限定；R101有占用或维修

**精确动作**

- user2以相同时段搜索

**结果与约束**

- 不返回上述不可预约项；筛选由资源公开接口判定，不能靠前端隐藏就放行下单

</details>

## 场景三

### 场景概述

搜索没有结果时提示没有空位；请求失败时提示错误和重试。页面不拿上次结果冒充本次可用座位。

### 操作步骤与预期结果

1. 用户打开座位搜索页面并提交查询。
2. 接口正常返回空列表时，页面显示没有可用座位。
3. 另一次查询遇到网络失败，页面显示必要错误和重试方式。
4. 失败时不把上一轮结果当作这次可用结果。

<details>
<summary>场景编号与精确规则补充（S026.SC03）</summary>

- 场景名称：没有空位和网络出错，要给出不同提示
- 场景编号：S026.SC03

**对应的业务要求**

- M1-01.AC1：按区域、日期、时段和插座一起筛选
- M1-01.AC2：只显示开放、有使用资格、没有占用或维修的座位

**精确条件**

- 资源接口分别返回空列表和网络失败

**精确动作**

- 执行两次独立搜索

**结果与约束**

- 空列表显示无可用座位；失败显示必要错误/重试；不回填上一轮结果冒充本次可用

</details>
