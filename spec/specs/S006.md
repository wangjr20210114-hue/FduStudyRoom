# 管理员设置预约时长和各类时限

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s006sc01"></a>

## 场景一

### 场景概述

管理员把最长预约时长从4小时改为2小时后，新预约立即按2小时检查，之前已经成立的预约不被悄悄改写。

### 操作步骤与预期结果

1. 管理员打开系统设置，当前最长预约时长为4小时。
2. 管理员按当前版本把上限改成2小时并保存。
3. 用户随后提交一笔3小时新预约，系统提示超过上限，不创建该预约。
4. 此前已经成功的预约保持原记录。

<details>
<summary>场景编号与精确规则补充（S006.SC01）</summary>

- 场景名称：修改最长预约时长，只影响之后的新预约
- 场景编号：S006.SC01

**对应的业务要求**

- IAM-04.AC1：最长预约默认4小时，管理员可以修改

**精确条件**

- 参数maxDurationHours=4

**精确动作**

- admin1按当前版本更新为2，之后发起新的3小时预约校验

**结果与约束**

- 新请求因超过2小时被拒绝；先前已成立预约不被静默改写

</details>

## 场景二

### 场景概述

管理员填写不合理的时限，或者拿旧版本设置保存时，系统说明错误并保留原配置，不能只更新一部分参数。

### 操作步骤与预期结果

1. 当前设置为开始前15分钟提醒、开始后10分钟提醒、开始后15分钟截止签到。
2. 管理员分别尝试把最长预约时长设为0、把提醒时间放到签到截止之后，以及提交旧版设置。
3. 每次保存都被拒绝，并说明对应问题。
4. 原配置及版本保持不变，不出现一部分新值、一部分旧值的情况。

<details>
<summary>场景编号与精确规则补充（S006.SC02）</summary>

- 场景名称：不合理或已经过时的设置不能保存
- 场景编号：S006.SC02

**对应的业务要求**

- IAM-04.AC2：提醒、签到截止、审批和维修时限先检查再保存，每次修改有版本和记录

**精确条件**

- 默认提醒为-15、+10、截止+15分钟

**精确动作**

- 提交最长时长0、提醒晚于截止、旧版本修改

**结果与约束**

- 每个非法请求有明确错误；配置及版本不变，不形成半套参数

</details>

## 场景三

### 场景概述

管理员修改审批和维修时限后，可以在变更记录中看到修改人、时间、前后值和版本。已有单据继续使用原截止时间，新单据才采用新设置。

### 操作步骤与预期结果

1. 示例中审批时限为60分钟，维修时限为120分钟。
2. 管理员把两项改成另一组大于0的数值并保存。
3. 打开设置变更记录，可以看到修改人、时间、原值、新值和版本。
4. 已有申请和工单保持原截止时间，之后新建的单据使用新时限。

<details>
<summary>场景编号与精确规则补充（S006.SC03）</summary>

- 场景名称：修改审批和维修时限后，能查到是谁改的
- 场景编号：S006.SC03

**对应的业务要求**

- IAM-04.AC2：提醒、签到截止、审批和维修时限先检查再保存，每次修改有版本和记录

**精确条件**

- 审批TTL测试60分钟，维修SLA测试120分钟

**精确动作**

- 修改为另一组正值并查询变更记录

**结果与约束**

- 记录操作者、前后值、版本和时间；已有单据保留创建时deadline快照，新单使用新值

</details>
