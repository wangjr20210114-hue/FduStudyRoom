# 维护人员开始维修后，停用整间教室并处理已有预约

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s052sc01"></a>

## 场景一

### 场景概述

维护人员点击开始维修，系统确认整间教室限制生效后，才显示维修中。全室座位不能新预约，并能追到工单来源。

### 操作步骤与预期结果

1. W1已分给worker1，R101两个座位原本可用。
2. worker1打开自己的任务，点击“开始维修”。
3. 系统通过真实资源接口确认限制，工单随后显示维修中。
4. 用户不能再新预约全室座位，来源指向W1，流程不直接改资源数据库。

<summary>场景编号与精确规则补充（S052.SC01）</summary>

- 场景名称：确认教室限制生效后，再显示维修中
- 场景编号：S052.SC01

**对应的业务要求**

- M3-03.AC1：进入维修中时，通过网络限制全室座位
- M3-03.AC2：保存待办以便重试，不直接修改预约或资源数据库

**精确条件**

- W1已分配worker1，R101两座当前可用

**精确动作**

- worker1开始维修，确认资源HTTP写回

**结果与约束**

- 仅资源限制确认后显示维修中；全室座位不可新预约，记录M3/W1来源；不直接写资源库

</details>

<a id="s052sc02"></a>

## 场景二

### 场景概述

开始维修时资源接口不可达，页面显示限制处理中或失败重试。服务恢复仍继续待办，不把尚未确认的下架说成已完成。

### 操作步骤与预期结果

1. 资源接口断网，W1准备开始维修。
2. 维护人员提交开始操作，页面显示限制处理中或失败重试。
3. 维修服务重启后，待办仍保存并可继续处理。
4. 系统不直接修改资源库，也不虚报已经下架。

<details>
<summary>场景编号与精确规则补充（S052.SC02）</summary>

- 场景名称：限制接口断网时，显示处理中或重试
- 场景编号：S052.SC02

**对应的业务要求**

- M3-03.AC2：保存待办以便重试，不直接修改预约或资源数据库

**精确条件**

- 资源接口断网，W1发起维修

**精确动作**

- 提交开始操作并重启服务

**结果与约束**

- 显示限制处理中/失败重试；任务持久保留；没有直接改资源数据库或不实“已下架”提示

</details>

<a id="s052sc03"></a>

## 场景三

### 场景概述

维修正式生效后，系统结束教室内尚未结束的个人预约并通知，不记违约；已结束历史保留，整室申请提示异常。

### 操作步骤与预期结果

1. R101有未来未签到、已签到未结束和已结束三类个人预约。
2. 维修限制生效，系统发送可重试的预约影响事件。
3. 前两类以维修原因结束并通知，不记违约；已结束记录不改。
4. 整室占用来源仍保留，并显示资源异常。

<details>
<summary>场景编号与精确规则补充（S052.SC03）</summary>

- 场景名称：维修影响尚未结束的预约，不改过去历史
- 场景编号：S052.SC03

**对应的业务要求**

- M3-03.AC3：已有预约怎么结束、怎样通知、历史怎样保留都有明确规则

**精确条件**

- R101存在未来BOOKED、已签到未结束和已结束预约

**精确动作**

- 维修生效并发送可重试影响事件

**结果与约束**

- 预约域按P05终结未结束项且不记违约并通知；已结束历史不变；整室来源保留并提示异常

</details>
