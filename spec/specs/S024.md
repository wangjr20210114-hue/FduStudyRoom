# 查询座位时，一起检查预约、维修和使用资格

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s024sc01"></a>

## 场景一

### 场景概述

查询可用座位时，系统一起检查预约、维修和院系资格，只把所有条件都符合的座位显示为可预约。

### 操作步骤与预期结果

1. A01已被预约、A02维修中；R102限定CS，而user2无资格。
2. user2查询09:00—10:00可用座位。
3. 这些不可用座位都不在可预约结果中，后端也实际检查，不靠前端隐藏。
4. 有权限的调用者可追查不可用原因。

<details>
<summary>场景编号与精确规则补充（S024.SC01）</summary>

- 场景名称：不把任何不符合条件的座位显示成可预约
- 场景编号：S024.SC01

**对应的业务要求**

- M1-01.AC2：只显示开放、有使用资格、没有占用或维修的座位

**精确条件**

- A01个人占用、A02维修限制、R102限CS且user2无资格

**精确动作**

- user2查询T的可用资源

**结果与约束**

- 不返回任何上述不可用座位；原因按授权粒度可追溯，不靠前端过滤

</details>

<a id="s024sc02"></a>

## 场景二

### 场景概述

一笔预约结束后，座位仍需检查其他限制。如果随后进入维修，同一时段不能再显示可预约。

### 操作步骤与预期结果

1. A01原预约到10:00结束，之后没有其他限制。
2. 用户查询10:00—11:00，座位显示可用。
3. 系统给A01添加维修限制后，用户再次查询同一时段，座位变为不可用。
4. 系统不因上一笔预约已结束就忽略维修状态。

<details>
<summary>场景编号与精确规则补充（S024.SC02）</summary>

- 场景名称：上一笔预约结束后，还要确认有没有维修等其他限制
- 场景编号：S024.SC02

**对应的业务要求**

- RES-04.AC2：结束时刻不占下一段时间；整室预约要么全成功，要么全失败
- RES-05.AC2：验收后只解除当前维修单的限制，其他维修、停用或整室占用仍有效

**精确条件**

- A01占用到10:00，10:00后无其他限制

**精确动作**

- 查询[10:00,11:00)，随后为其添加维修限制再查

**结果与约束**

- 第一次可用，第二次不可用；不能仅按预约结束忽略维修

</details>

## 场景三

### 场景概述

统计通过资源公开接口取得座位开放容量，结果说明时段和算法；已有预约不应减少总可服务容量。

### 操作步骤与预期结果

1. R101两个座位在08:00—12:00开放，没有停用或维修。
2. 统计功能通过公开接口查询这段时间的可服务总时长。
3. 结果为480个座位分钟，并说明计算区间和算法；已有预约不从这个总容量中扣除。
4. 调用方无需直接查询资源模块的私有数据库表。

<details>
<summary>场景编号与精确规则补充（S024.SC03）</summary>

- 场景名称：统计能取得开放容量，不必直接读别人的数据库
- 场景编号：S024.SC03

**对应的业务要求**

- SUP-03.AC3：从真实业务查询和公开接口取得，不读别的模块私有库

**精确条件**

- R101两座在08:00—12:00开放，无停用/维修

**精确动作**

- 通过公开读取接口查询资源可服务分钟

**结果与约束**

- 提供480座位分钟及口径/区间，调用方不读本模块私表；分母不因已有预约缩小

</details>
