# 取消工单时，确认维修中的教室是否安全

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s056sc01"></a>

## 场景一

### 场景概述

工单还没开始维修时，报修人或管理员可以按权限取消。普通用户不能取消别人的工单，未产生的资源限制也不需要释放。

### 操作步骤与预期结果

1. W1为新建或已分配状态，尚无维修限制。
2. 报修人打开自己的工单并取消，系统保存取消结果。
3. 报修人和已分配执行人收到通知，不凭空产生资源释放。
4. 无权用户取消另一人的工单，被拒绝。

<details>
<summary>场景编号与精确规则补充（S056.SC01）</summary>

- 场景名称：还没开修时，报修人或管理员可以取消
- 场景编号：S056.SC01

**对应的业务要求**

- M3-07.AC1：说明谁能在什么状态取消；维修中的取消要走审批
- M3-07.AC3：将结果通知报修人和执行人

**精确条件**

- W1为NEW或ASSIGNED，尚无维修限制

**精确动作**

- 报修人取消，再由他人尝试取消另一人的工单

**结果与约束**

- 本人取消成功并通知报修人/已分配执行人；越权取消拒绝；不制造资源释放

</details>

<a id="s056sc02"></a>

## 场景二

### 场景概述

维修中申请取消要先经过独立安全验收。等待或否决期间教室仍受限制，确认安全后才取消并恢复本工单影响。

### 操作步骤与预期结果

1. W1维修中，限制有效，用户发起取消申请。
2. 等待期间仍不释放资源。
3. 独立验收方否决时，工单继续维修；另一次独立情形确认安全时，才取消并安排解除W1限制。
4. 维修人不能自己确认安全。

<details>
<summary>场景编号与精确规则补充（S056.SC02）</summary>

- 场景名称：维修中的工单，取消前还要有人确认安全
- 场景编号：S056.SC02

**对应的业务要求**

- M3-07.AC1：说明谁能在什么状态取消；维修中的取消要走审批

**精确条件**

- W1为IN_PROGRESS且限制有效

**精确动作**

- 发起取消申请，再分别由独立验收方否决或确认安全

**结果与约束**

- 申请期间限制不释放；否决继续维修；确认安全后才CANCELLED并发解除本源任务，维修人不能自行确认

</details>

<a id="s056sc03"></a>

## 场景三

### 场景概述

已经安全取消的工单重复收到取消或释放请求，仍返回原结果，不重复通知，也不解除同教室其他限制。

### 操作步骤与预期结果

1. W1已安全取消，W2仍限制同一教室。
2. 系统再次处理W1取消和释放请求。
3. 结果不变，不重复通知或释放，W2限制及整室占用继续有效。

<details>
<summary>场景编号与精确规则补充（S056.SC03）</summary>

- 场景名称：取消后再重复操作，仍不能解除另一张工单的限制
- 场景编号：S056.SC03

**对应的业务要求**

- M3-07.AC2：重复请求不多次恢复，其他工单限制仍保留
- M3-07.AC3：将结果通知报修人和执行人

**精确条件**

- W1安全取消，W2仍限制同室

**精确动作**

- 重放W1取消/释放命令

**结果与约束**

- 逻辑结果不变，不重复通知/释放；W2限制和整室占用仍生效

</details>
