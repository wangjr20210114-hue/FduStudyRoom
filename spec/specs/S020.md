# 查清座位为什么被占用，并避免重复操作

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s020sc01"></a>

## 场景一

### 场景概述

查询座位不可用原因时，系统区分个人预约、整室申请和维修，并按权限显示来源，不泄露他人的敏感申请内容。

### 操作步骤与预期结果

1. 系统中分别存在个人占用、整室占用和维修限制。
2. 按座位和时段查询不可用原因。
3. 有权限时，结果显示对应业务类别、编号、版本和时间。
4. 没有权限的人看不到他人申请中的敏感正文。

<details>
<summary>场景编号与精确规则补充（S020.SC01）</summary>

- 场景名称：能区分个人预约、整室预约和维修
- 场景编号：S020.SC01

**对应的业务要求**

- RES-06.AC1：能对应到个人预约、整室申请或维修，保留业务编号、版本和时间

**精确条件**

- 分别存在个人占用、M2整室占用和M3维修限制

**精确动作**

- 按座位和时段查询原因

**结果与约束**

- 返回M1/M2/M3、各自业务ID、版本及时间；没有权限者不能读他人敏感申请正文

</details>

<a id="s020sc02"></a>

## 场景二

### 场景概述

同一次整室占用请求原样重发时返回原结果；沿用操作编号却修改时段时，系统拒绝，不更改原占用。

### 操作步骤与预期结果

1. 整室申请Q1第1版已成功占用指定时段。
2. 原样重发请求，系统返回同一结果，不增加占用。
3. 沿用同一操作编号把时段改掉再提交，系统提示冲突，原结果不变。

<details>
<summary>场景编号与精确规则补充（S020.SC02）</summary>

- 场景名称：同一次请求重发不会多占座，改了内容也不能冒充同一次
- 场景编号：S020.SC02

**对应的业务要求**

- RES-06.AC2：相同编号和内容重试返回原结果；沿用编号但改内容时拒绝

**精确条件**

- 已成功处理source=M2、businessId=Q1、version=1、T

**精确动作**

- 重放同参，再以同键改变时段

**结果与约束**

- 同参返回同一逻辑结果且不多占；异参冲突且旧结果不变

</details>

<a id="s020sc03"></a>

## 场景三

### 场景概述

审批服务通过真实网络接口落实教室占用，资源结果保留业务来源，流程服务不需要直接访问资源表。

### 操作步骤与预期结果

1. 流程服务没有资源数据库连接权限。
2. 流程服务通过真实HTTP接口发送占用请求。
3. 资源服务正确更新并保留该申请的来源，不要求调用方读写资源表或引用内部Java类。

<details>
<summary>场景编号与精确规则补充（S020.SC03）</summary>

- 场景名称：审批服务通过网络接口占用教室
- 场景编号：S020.SC03

**对应的业务要求**

- RES-06.AC3：调用方通过网络接口更新，不直接访问资源数据库

**精确条件**

- 流程服务无资源库连接权限

**精确动作**

- 用真实HTTP写入来源占用并检查资源结果

**结果与约束**

- 资源更新成功且保留来源；流程服务不需要直接访问资源表或内部Java类

</details>
