# 实际发送邮件，失败可重试，结果不明就提示待核实

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s078sc01"></a>

## 场景一

### 场景概述

系统通过实际邮件服务发送提醒，收件箱能收到包含教室和时段的邮件。测试收件成功只证明测试链路，不代表正式邮件已验收。

### 操作步骤与预期结果

1. 独立测试邮件服务和收件箱已配置，正式投递另需真实可用服务。
2. 系统发送通知事件N1，打开测试收件箱核对。
3. 能看到真实生成的邮件和业务教室、时段。
4. 正式服务尚未具备时，仅记录测试链路通过，不称正式投递已验收。

<details>
<summary>场景编号与精确规则补充（S078.SC01）</summary>

- 场景名称：测试收件箱里能真正收到邮件
- 场景编号：S078.SC01

**对应的业务要求**

- SUP-01.AC3：真实邮件提醒使用可配置的邮件发送服务
- M1-05.AC3：发送真实邮件需要邮件服务，测试时用能实际查看的测试收件箱

**精确条件**

- 配置独立测试SMTP/收件箱，生产终验另用可用真实服务

**精确动作**

- 发送逻辑事件N1并在收件箱核对

**结果与约束**

- 真实SMTP产生可观察邮件，内容含业务教室/时段；生产服务未具备时仅标测试链路通过

## 场景二

### 场景概述

邮件服务明确拒绝发送后，系统显示失败原因和重试时间；服务恢复后安全重试，状态与实际收件结果一致。

### 操作步骤与预期结果

1. 邮件服务明确拒绝第一次请求，任务不标送达。
2. 用户查看失败原因和下次重试时间。
3. 服务恢复后系统再次执行，状态与实际收件一致。
4. 同一业务事件不增加另一份逻辑通知。

<details>
<summary>场景编号与精确规则补充（S078.SC02）</summary>

- 场景名称：明确发送失败后，可以按计划重试
- 场景编号：S078.SC02

**对应的业务要求**

- SUP-01.AC2：可确认失败的邮件支持重试，结果可见，不能虚称送达

**精确条件**

- SMTP明确拒绝第一次请求后恢复

**精确动作**

- 查看失败及next_retry并再次运行任务

**结果与约束**

- 首次不标送达，安全重试后状态与收件箱一致；同逻辑事件不多建通知

</details>

## 场景三

### 场景概述

邮件可能已被接收但确认丢失时，投递任务显示待核实，不盲目重发，也不虚称可以保证外部绝不重复。

### 操作步骤与预期结果

1. 外部邮件服务可能已接收，发送方未收到确认。
2. 用户打开投递任务，看到待核实而非成功。
3. 系统再次调度时不盲目重发。
4. 若要求外部严格不重复，仍需投递方防重复能力或人工核对，当前不能凭空保证。

<details>
<summary>场景编号与精确规则补充（S078.SC03）</summary>

- 场景名称：可能已发出却没收到确认时，不盲目重发
- 场景编号：S078.SC03

**对应的业务要求**

- SUP-01.AC2：可确认失败的邮件支持重试，结果可见，不能虚称送达

**精确条件**

- SMTP可能接收但发送方没获得确认

**精确动作**

- 查看任务并再次调度

**结果与约束**

- 显示待核实而非成功，不盲重发；严格外部恰一次依赖提供方幂等或人工核对，不虚构保证

</details>
