# 查看整室申请进度、办理记录和状态通知

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s043sc01"></a>

## 场景一

### 场景概述

申请列表和审批任务分别按身份权限展示，指定他人申请编号也不能读取不该看的详情或用途。

### 操作步骤与预期结果

1. applicant1有Q1、user2有Q2，admin1只获授权办理当前任务。
2. 申请人打开自己的列表，只看到本人申请。
3. 审批人打开任务列表，只看到授权范围。
4. 任一账号指定无权查看的申请详情时被拒绝，不泄露他人用途。

- 申请人只见本人；审批人只见授权任务/范围，越权详情拒绝，不泄漏他人用途

## 场景二

### 场景概述

申请详情的时间线按顺序展示每次审批的人、时间、结果和理由，后面的决定不会覆盖前面的记录。

### 操作步骤与预期结果

1. Q1经历一级通过、二级驳回。
2. 用户打开Q1详情并查看办理时间线。
3. 每一步可见处理人、时间、结果和流程版本，驳回还包含必要理由。
4. 后续状态不覆盖旧审批记录。

<details>
<summary>场景编号与精确规则补充（S043.SC02）</summary>

- 场景名称：能看到每一级是谁在什么时候作了什么决定
- 场景编号：S043.SC02

**对应的业务要求**

- M2-05.AC2：每次决定保存处理人、时间、结果和必要理由

**精确条件**

- Q1经历一级通过及二级驳回

**精确动作**

- 查看申请时间线

**结果与约束**

- 逐项有处理人、时间、结果、流程/版本和必要驳回理由；旧记录不被更新覆盖

</details>

<a id="s043sc03"></a>

## 场景三

### 场景概述

整室申请通过、驳回和撤销时产生对应通知；已落实教室遇维修，申请提示资源异常并通知用户，但不自动删除整室占用。

### 操作步骤与预期结果

1. 分别发生申请通过、驳回和撤销，另有一笔已落实申请遇到维修。
2. 用户查看申请进度、通知和相关操作记录，正常变化都有对应事件。
3. 维修影响的申请显示资源异常并通知，不再声称仍可正常使用。
4. 系统保留原整室占用来源，不自动释放。

<details>
<summary>场景编号与精确规则补充（S043.SC03）</summary>

- 场景名称：状态变化有通知，已订教室遇维修也要提醒
- 场景编号：S043.SC03

**对应的业务要求**

- M2-05.AC3：状态变化产生对应通知和操作记录

**精确条件**

- Q1发生通过/驳回/撤销；另一已落实单遇维修

**精确动作**

- 读取通知和审计并查看进度

**结果与约束**

- 正常状态变更各有对应事件；维修单标资源异常并通知但不自动释放整室来源；不虚称仍能使用

</details>
