# 维修人申请完工，由另一人验收后再恢复

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s054sc01"></a>

## 场景一

### 场景概述

维修人提交完工后，工单进入待验收，教室仍受限制。维修人不能自行验收自己的工单，座位不会因此直接恢复。

### 操作步骤与预期结果

1. worker1处理W1后提交完工，打开详情看到待验收。
2. worker1尝试验收自己的W1，系统拒绝。
3. 资源仍受W1限制，未因申请完工或自验尝试恢复。

## 场景二

### 场景概述

独立验收人说明原因并判定不通过后，工单继续维修，保留返工过程并通知相关人员，教室限制不解除。

### 操作步骤与预期结果

1. admin2有验收权限且不是W1维修人，打开验收页面。
2. 填写非空理由，选择验收不通过。
3. 工单继续维修并保存返工记录，W1限制仍在。
4. 维修人和报修人收到对应通知。

<details>
<summary>场景编号与精确规则补充（S054.SC02）</summary>

- 场景名称：验收没通过，说明原因后继续维修
- 场景编号：S054.SC02

**对应的业务要求**

- M3-05.AC2：验收不通过就继续维修，不能提前恢复座位

**精确条件**

- admin2具验收权限且不是worker1

**精确动作**

- 以非空理由验收不通过

**结果与约束**

- 继续维修并保留返工记录，W1限制不解除；通知维修人与报修人

</details>

<a id="s054sc03"></a>

## 场景三

### 场景概述

独立验收通过后只解除当前工单的限制；同教室还有另一张维修单时，不能一起恢复，结果未确认则显示待恢复。

### 操作步骤与预期结果

1. W1、W2都限制R101，admin2独立验收W1。
2. admin2选择验收通过，系统调用真实资源解除接口。
3. 只有W1限制解除，W2仍有效，座位不能因此全部恢复。
4. 如果解除结果尚未确认，页面明确显示待恢复。

<details>
<summary>场景编号与精确规则补充（S054.SC03）</summary>

- 场景名称：验收通过只解除这张工单的限制
- 场景编号：S054.SC03

**对应的业务要求**

- M3-05.AC3：通过后通过网络解除这张工单自己的限制

**精确条件**

- W1/W2同时限制R101，admin2独立验收W1

**精确动作**

- 通过并调用真实资源解除接口

**结果与约束**

- W1限制解除，W2仍有效，座位不因只完成W1就恢复；若资源确认未知则明确待恢复状态

</details>
