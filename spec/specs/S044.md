# 审批结果同步失败后，保存待办并自动核对

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s044sc01"></a>

## 场景一

### 场景概述

最终审批已保存但同步前服务停止，恢复后系统继续原来的待办，用户能看到失败和重试进度。

### 操作步骤与预期结果

1. 最终决定已保存，同步资源前审批服务意外停止。
2. 服务恢复后，用户打开申请进度。
3. 系统从已保存待办继续，沿用原申请编号、动作和版本。
4. 页面和任务详情显示真实失败、重试及结果。

<details>
<summary>场景编号与精确规则补充（S044.SC01）</summary>

- 场景名称：审批服务重启后，继续同步尚未确认的占用
- 场景编号：S044.SC01

**对应的业务要求**

- M2-06.AC1：保存业务结果时也保存待重试任务，进程退出后可恢复

**精确条件**

- 最终决策已提交，可重试任务尚未确认

**精确动作**

- 在发送前杀进程再重启

**结果与约束**

- 从持久状态恢复原命令，复用申请ID/动作/版本；页面和任务详情可见失败及重试

</details>

## 场景二

### 场景概述

已撤销申请收到旧占用成功消息时，不会重新变为成功；重复释放也不影响其他申请或维修限制。

### 操作步骤与预期结果

1. Q1已撤销，新版本释放操作已发出。
2. 旧版占用确认到达，系统保持撤销状态。
3. 同一释放再次到达，系统返回原结果，不误改其他申请或工单限制。

<details>
<summary>场景编号与精确规则补充（S044.SC02）</summary>

- 场景名称：已撤销的申请，不会被旧成功消息恢复
- 场景编号：S044.SC02

**对应的业务要求**

- M2-06.AC2：用业务来源编号和版本识别重复或旧消息，失败能看到

**精确条件**

- Q1已撤销并发布新版本释放

**精确动作**

- 发送旧版本占用确认及重复释放

**结果与约束**

- 旧占用不复活；同源释放幂等，其他申请/工单限制保留

</details>

<a id="s044sc03"></a>

## 场景三

### 场景概述

申请同步遇到断网时不假报成功；网络恢复后系统核对原操作，使申请状态和资源结果一致，并保留追踪信息。

### 操作步骤与预期结果

1. 申请正在同步，流程与资源服务间网络暂时中断。
2. 用户打开进度，页面显示真实未确认状态，不显示虚假成功。
3. 网络恢复后再次查看，系统按原操作核对，状态与资源一致。
4. 保留来源和追踪记录，不直接改对方数据库修复。

<details>
<summary>场景编号与精确规则补充（S044.SC03）</summary>

- 场景名称：断网时不报成功，恢复后申请和资源一致
- 场景编号：S044.SC03

**对应的业务要求**

- M2-06.AC3：实际通过网络把服务连起来验证后，才算业务完成

**精确条件**

- 资源服务和流程服务真实隔离部署

**精确动作**

- 阻断网络、恢复网络并运行对账

**结果与约束**

- 阻断期间不假成功，不直接改库；恢复后状态收敛且留trace和来源记录

</details>
