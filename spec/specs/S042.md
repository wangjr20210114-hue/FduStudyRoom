# 撤销申请、处理到期，并正确释放整室占用

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s042sc01"></a>

## 场景一

### 场景概述

未落实的申请到审批截止时自动撤销并释放自己的可能占用；已经落实的预约不受审批截止影响。

### 操作步骤与预期结果

1. Q1尚未落实，截止为09:00。
2. 08:59:59处理到期任务，申请继续保留。
3. 09:00再次处理，系统撤销Q1，只释放它可能已产生的占用，重复处理也不多释放。
4. 已落实申请不会因审批期限到达自动取消。

<details>
<summary>场景编号与精确规则补充（S042.SC01）</summary>

- 场景名称：审批期限到了，只撤销尚未落实的申请
- 场景编号：S042.SC01

**对应的业务要求**

- M2-04.AC1：未落实申请到截止自动撤销，申请人也可按规则主动撤销
- M2-04.AC2：驳回或撤销只释放本申请资源，重复处理不多释放

**精确条件**

- Q1 expires_at=09:00且尚未落实

**精确动作**

- 分别在08:59:59、09:00运行到期任务

**结果与约束**

- 前者保留，后者撤销并幂等释放本申请可能的资源；已落实单不因审批截止自动取消

</details>

## 场景二

### 场景概述

申请开始前，申请人可以撤销自己的申请；其他用户不能代撤销。开始后普通申请人不再能撤销，管理员另需权限和理由。

### 操作步骤与预期结果

1. Q1属于applicant1，10:00开始，当前09:30。
2. user2尝试撤销，系统拒绝。
3. applicant1撤销并重复一次，系统保持同一撤销结果，不影响其他来源。
4. 另对已开始申请尝试普通用户撤销，系统拒绝；管理员操作需权限及理由。

<details>
<summary>场景编号与精确规则补充（S042.SC02）</summary>

- 场景名称：开始前申请人可以撤销，其他人不能代撤销
- 场景编号：S042.SC02

**对应的业务要求**

- M2-04.AC1：未落实申请到截止自动撤销，申请人也可按规则主动撤销
- M2-04.AC2：驳回或撤销只释放本申请资源，重复处理不多释放

**精确条件**

- Q1在10:00开始，now=09:30，applicant1为申请人

**精确动作**

- user2撤销后由applicant1撤销并重复一次

**结果与约束**

- user2被拒；本人撤销成功且重复不影响其他来源；开始后普通申请人撤销被拒，管理员需理由

</details>

<a id="s042sc03"></a>

## 场景三

### 场景概述

资源确认与审批到期同时发生时，申请只能保留一个有效结果；若撤销生效，后来确认的占用要补做释放。

### 操作步骤与预期结果

1. Q1正在确认资源，时间到达审批截止。
2. 系统同时处理资源最终回复和到期撤销。
3. 最终只有一个有效结果；撤销先完成时，迟到占用会被释放。
4. 用户不能看到已撤销申请仍长期占着座位的结果。

<details>
<summary>场景编号与精确规则补充（S042.SC03）</summary>

- 场景名称：确认教室和到期撤销撞在一起，也不会撤销后仍占座
- 场景编号：S042.SC03

**对应的业务要求**

- M2-04.AC3：到期和审批同时发生，不能留下已撤销却仍占座的结果

**精确条件**

- Q1资源确认在途，now推进expires_at

**精确动作**

- 同时执行最终响应处理和超时撤销

**结果与约束**

- 只允许一个有效终态；若撤销胜出，迟到占用必须补偿释放，不能出现已撤销仍占座

</details>
