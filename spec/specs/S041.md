# 最后一级通过后，确认整间教室确实订下

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s041sc01"></a>

## 场景一

### 场景概述

最后一级审批通过后，系统通过资源接口确认整间教室占用。只有所有座位都订下，申请才显示已落实。

### 操作步骤与预期结果

1. Q1两级审批已通过，R101两个座位在指定时段空闲。
2. 审批服务通过真实资源接口提交整室占用请求。
3. 所有座位确认后，用户打开Q1看到已落实，来源记录对应Q1和该时段。
4. 同步不直接改资源数据库。

<details>
<summary>场景编号与精确规则补充（S041.SC01）</summary>

- 场景名称：所有座位都确认占用后，申请才显示已落实
- 场景编号：S041.SC01

**对应的业务要求**

- M2-03.AC1：最后一级通过后，调用资源接口统一占用
- M2-03.AC3：整个时段的全部座位都覆盖，并能追到对应整室申请

**精确条件**

- Q1两级通过，R101两座在T无冲突

**精确动作**

- 最终审批通过后调用资源公开HTTP并查询申请

**结果与约束**

- 全部座位占用确认后才展示已落实；来源M2/Q1覆盖T，不写资源私库

</details>

<a id="s041sc02"></a>

## 场景二

### 场景概述

整室审批通过时，如果已有个人预约占了一个座位，申请仍不能显示已落实，也不能把剩余座位先占下来。

### 操作步骤与预期结果

1. A01在该时段已有个人预约，Q1完成最终审批。
2. 系统尝试落实整室占用。
3. 申请显示资源冲突或未落实，不显示已通过并落实。
4. A02不留下这次整室占用，A01的原预约不变。

<details>
<summary>场景编号与精确规则补充（S041.SC02）</summary>

- 场景名称：有人已经订走一个座位，就不能把整室显示为成功
- 场景编号：S041.SC02

**对应的业务要求**

- M2-03.AC2：座位冲突时不能显示申请已落实

**精确条件**

- A01的T有个人预约，Q1最终审批完成

**精确动作**

- 尝试落实整室占用

**结果与约束**

- 申请显示资源冲突/未落实而非APPROVED；A02无本申请残留，原预约不变

</details>

<a id="s041sc03"></a>

## 场景三

### 场景概述

落实整室占用时遇到网络超时，页面先显示资源确认中，系统沿用原操作核对，得到真实结果后才显示成功。

### 操作步骤与预期结果

1. 资源接口调用超时，结果暂时不明。
2. 用户打开Q1，页面显示资源确认中。
3. 系统使用同一申请编号和版本重试核对，不新增另一份整室占用。
4. 取得真实确认后，申请才显示成功。

<details>
<summary>场景编号与精确规则补充（S041.SC03）</summary>

- 场景名称：网络超时看不清结果时，先显示正在确认
- 场景编号：S041.SC03

**对应的业务要求**

- M2-03.AC1：最后一级通过后，调用资源接口统一占用
- M2-03.AC2：座位冲突时不能显示申请已落实

**精确条件**

- 资源调用超时无法确认结果

**精确动作**

- 查询Q1并重试同一命令

**结果与约束**

- 先显示资源确认中；相同业务ID/版本对账，不新建整室占用，取得真实确认后才成功

</details>
