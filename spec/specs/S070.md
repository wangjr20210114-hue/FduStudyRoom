# 用AI助手提交整室申请、查进度和撤销

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s070sc01"></a>

## 场景一

### 场景概述

助手帮助提交整室申请时仍检查用户资格。有资格的人确认后得到待审批编号，无资格的人被拒绝。

### 操作步骤与预期结果

1. applicant1有整室资格，user1没有。
2. 两人分别要求申请R101的10:00—12:00，查看预览并确认。
3. applicant1通过公开接口得到待审批申请编号；user1被业务权限拒绝。
4. 助手不自行授予资格，也不把待审批说成已通过。

## 场景二

### 场景概述

用户向助手问申请进度，助手读取真实状态并说明当前审批级别，不根据聊天猜测已经通过。

### 操作步骤与预期结果

1. Q1仍在等待第二级审批。
2. 用户向助手询问Q1进度。
3. 助手调用真实状态接口，返回当前阶段，不因聊天里出现“应该通过”而改成已落实。

<summary>场景编号与精确规则补充（S070.SC02）</summary>

- 场景名称：问进度时，回答实际到哪一级
- 场景编号：S070.SC02

**对应的业务要求**

- AGT-01.AC1：通过预约、审批、报修公开接口真正执行主要操作

**精确条件**

- 申请Q1尚待二级审批

**精确动作**

- 询问Q1进度

**结果与约束**

- 调用真实申请状态接口并展示当前阶段；不依据聊天中“应该通过”改成已落实

</details>

## 场景三

### 场景概述

用户通过助手撤销整室申请时，也要先确认。取消确认就不修改，重新确认后才按业务规则撤销并保留释放结果。

### 操作步骤与预期结果

1. Q1属于当前申请人且未开始，用户要求撤销。
2. 助手提示确认，用户选择取消，本次不调用修改接口。
3. 用户重新提出并确认，助手调用公开撤销流程，保留对应资源释放结果。
4. 系统不直接删除申请库记录。

<details>
<summary>场景编号与精确规则补充（S070.SC03）</summary>

- 场景名称：撤销前也要确认，不确认就不修改
- 场景编号：S070.SC03

**对应的业务要求**

- AGT-01.AC1：通过预约、审批、报修公开接口真正执行主要操作
- AGT-01.AC2：时间地点不清楚先问，敏感操作按实际用户权限处理

**精确条件**

- Q1属于当前申请人且未开始

**精确动作**

- 要求撤销，先取消确认，再重新请求并确认

**结果与约束**

- 第一次不调用写接口；确认后调用公开撤销且保留来源释放结果；不能直接删除申请库记录

</details>
