# 用户上报故障并查看自己的报修

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s050sc01"></a>

## 场景一

### 场景概述

用户打开报修页面，选择教室、按需选择座位并填写故障说明，提交后生成本人新工单，不立即进入维修或停用资源。

### 操作步骤与预期结果

1. user1登录，R101和A01存在，打开报修页面。
2. 选择R101，需要时再选A01，填写非空故障说明。
3. 点击提交，系统生成属于本人的新工单，可按权限查看详情。
4. 此时仅为上报，不自动显示维修中，也不立即下架座位。

## 场景二

### 场景概述

报修说明为空、教室不存在或座位不属于所选教室时，系统拒绝提交，资源状态不变。

### 操作步骤与预期结果

1. A01属于R101，系统还登记了R102。
2. 用户分别提交空说明、不存在教室、R102搭配A01的请求。
3. 每次都被拒绝，不生成工单，不改变教室或座位的可用性。

<details>
<summary>场景编号与精确规则补充（S050.SC02）</summary>

- 场景名称：位置或说明填错时，不创建工单
- 场景编号：S050.SC02

**对应的业务要求**

- M3-01.AC1：选择真实教室，需要时选座位，故障说明必填

**精确条件**

- A01属于R101，R102存在

**精确动作**

- 分别提交空说明、不存在教室、R102+A01组合

**结果与约束**

- 各次拒绝且不建工单、不改资源可用性

<a id="s050sc03"></a>

## 场景三

### 场景概述

用户只能查看自己的报修单，管理员按调度权限查看，不能通过修改请求里的用户编号获得额外权限。

### 操作步骤与预期结果

1. user1和user2各有工单。
2. user1指定user2工单编号查看详情，被拒绝。
3. 有调度权限的管理员查询，只得到授权范围内的工单。
4. 页面自填的用户编号不会扩大实际权限。

<details>
<summary>场景编号与精确规则补充（S050.SC03）</summary>

- 场景名称：用户只看自己的报修，管理员按调度权限查看
- 场景编号：S050.SC03

**对应的业务要求**

- M3-01.AC2：用户看自己的工单，管理员看获授权调度范围

**精确条件**

- user1与user2各有工单

**精确动作**

- user1指定user2工单ID，再由有调度权限管理员查询

**结果与约束**

- 普通用户越权拒绝；管理员仅按获授权调度范围查看，不因前端传userId越权

</details>
