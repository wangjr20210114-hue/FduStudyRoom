# 登录、重新打开页面和退出

> 业务需求草案；页面和按钮名称用于说明计划中的功能，不表示已经实现。

<a id="s003sc01"></a>

## 场景一

### 场景概述

普通用户、管理员和维护人员都使用本系统账号登录。登录后重新打开需要身份验证的页面，系统恢复当前账号的身份和可用功能。

### 操作步骤与预期结果

1. 分别使用已启用的user1、admin1和worker1打开登录页面。
2. 各账号输入自己的正确密码并提交，系统按实际身份完成登录，不跳转学校登录。
3. 登录后重新打开需要登录的页面，页面恢复该账号的信息和可用功能。
4. 身份由后端确认，返回内容不暴露密码材料。

<details>
<summary>场景编号与精确规则补充（S003.SC01）</summary>

- 场景名称：普通用户、管理员和维护人员都能登录
- 场景编号：S003.SC01

**对应的业务要求**

- IAM-01.AC3：普通用户、管理员和维护人员分别使用自己的账号
- USR-06.AC1：不要求复旦学号、学校密码或学校登录，注册默认普通用户

**精确条件**

- user1、admin1、worker1均有有效密码且启用

**精确动作**

- 分别登录并重新打开受保护页面

**结果与约束**

- 角色及权限来自后端会话，不接UIS
- 页面恢复本人身份；响应不泄漏密码材料

</details>

## 场景二

### 场景概述

用户输入错误密码时不能建立新的登录状态。即使已有登录信息，缺少防冒用标记的修改请求也不能执行。

### 操作步骤与预期结果

1. user1已有一次有效登录。
2. 用户在登录页面输入错误密码并提交，系统拒绝这次登录，不建立新登录状态。
3. 使用已有登录信息发送缺少防冒用标记的修改请求，后端仍拒绝处理。
4. 业务数据保持不变，原有安全检查继续生效。

<details>
<summary>场景编号与精确规则补充（S003.SC02）</summary>

- 场景名称：密码错了不能登录，不安全的修改请求不能执行
- 场景编号：S003.SC02

**对应的业务要求**

- IAM-01.AC2：安全处理密码，使用登录凭据和防冒用检查；退出后原登录失效

**精确条件**

- user1已登录，保存当前Cookie

**精确动作**

- 先以错误密码登录，再用缺CSRF的写请求调用受保护接口

**结果与约束**

- 错误密码不能建立会话；缺CSRF的写请求被拒绝
- 业务数据不变，已有安全策略不得降级

</details>

<a id="s003sc03"></a>

## 场景三

### 场景概述

用户在一个标签页退出后，另一个使用同一次登录的标签页也失去访问权限，不能继续显示或操作原来的私人数据。

### 操作步骤与预期结果

1. user1在两个标签页中使用同一次登录。
2. 用户在第一个标签页点击“退出”，系统撤销这次登录。
3. 用户回到第二个标签页继续访问，系统拒绝旧登录信息，页面清除受保护内容并返回登录页。
4. 再次使用旧登录凭据请求数据仍被拒绝，不恢复退出前的私人内容。

<details>
<summary>场景编号与精确规则补充（S003.SC03）</summary>

- 场景名称：退出后，另一个标签页也不能继续操作
- 场景编号：S003.SC03

**对应的业务要求**

- IAM-01.AC2：安全处理密码，使用登录凭据和防冒用检查；退出后原登录失效

**精确条件**

- user1在两个标签页使用当前会话

**精确动作**

- 在一个标签页退出，另一个用旧Cookie发请求

**结果与约束**

- 旧会话被拒绝；前端清除受保护内容并回到登录，不恢复旧页面数据

</details>
