# 自习室项目成员入口

## 执行条件

成员用已登录 Codex 的 IDE 打开解压后的个人包，或打开入组时建立的项目。全程使用当前对话。安装、检查、构建及 Git 操作由技能执行。

## 输入

从对话取得目标。从个人包或本机绑定自动确定代号和模块。首次登记时，使用成员在对话中填写或确认的 GitHub 用户名。由助手调用内部工具读取凭据，勿展示或要求成员粘贴个人包的配置。

## 执行过程

### Stage 1 定位成员与进度

定位当前目录的 `.agents/skills/campus-join/scripts/join.py`。以下 `helper` 都指这个文件的绝对路径，`py` 指本机兼容的 Python。调用 `py -X utf8 helper status`，取得项目目录、模块、已绑定账号和上次准备结果。Python 尚未安装时，由技能按[系统准备](references/host.md)处理。仅查询时，如未入组，直接报告本机进度。

### Stage 2 准备项目与确认账号

首次入组、修复或未完成的准备进入此阶段。按系统准备指引检查工具并启动 Docker，再调用 `py -X utf8 helper prepare`。成员已经给出 GitHub 用户名时，通过单个 `--github` 参数传入。助手在当前对话处理这些结果：

| 工具返回 | 助手的下一步 |
| --- | --- |
| GITHUB_LOGIN_REQUIRED | 调用 `gh auth login --hostname github.com --git-protocol https --web --clipboard` 进入设备授权，让成员在本人浏览器完成确认。工具需要回车时由助手输入。授权完成后重试。 |
| CONFIRM_GITHUB_ACCOUNT | 在对话中显示返回的用户名，由成员确认后用该用户名重试。 |
| GITHUB_ACCOUNT_MISMATCH | 核对成员指定的账号，用 `gh auth switch --hostname github.com --user 用户名` 切换已登录账号，或引导本人在浏览器授权目标账号后重试。已有绑定以数字 ID 校验。 |
| INVITATION_PENDING | 已登记。稍后重试，接收本项目的邀请并核实写权限。协调人执行机离线时说明等待原因，保留绑定。 |

工具检出冻结基线，校验缓冲站本人前后端权限，准备五个开发技能和测试环境。只有工具成功退出且返回“项目就绪”才报告准备成功。系统要求重启时告诉成员要点击什么；重启后在同一目录说“继续”，从已有记录恢复。

### Stage 3 在同一对话继续成员目标

以工具返回的项目路径作为后续工作目录。读取该目录的 AGENTS.md 和 `.agents/skills/` 下对应技能，使用其中的项目工具。技能版本检查指定该项目的 `.agents/skills` 目录。

| 成员的目标 | 接续操作 |
| --- | --- |
| 帮我入组 | 完成准备，报告本人模块和项目路径。 |
| 看看待办或交付到哪了 | 调用 campus-workflow 的只读预览，分别读取本人前后端需求及真实交付记录。 |
| 启动本地产品 | 调用 campus-build 启动主应用，验证服务后返回可打开的地址。 |
| 继续我的未完成需求 | 调用 campus-workflow，使用已验证的身份、模块和工作单，按后端、前端分别恢复。按场景执行需求对齐、限界 TDD 和回归。 |
| 交付本轮改动 | 从本人已有工作单和收据进入 campus-workflow 的交付阶段，补齐缺失的前置验证。按同一差异提交缓冲站并推送 GitHub，读取真实结果。 |

### Stage 4 核对交付

开发或交付时跟踪相应 GitHub 分支 CI 和华为体验站部署。Gitee 进度从缓冲站读取，人工验收及独立 CI 通过后，由执行机按发布策略推功能分支。待审核、待发布或受阻时，列出单号、当前阶段及下一项动作。

## 输出

按本次目标返回项目路径、模块、待办、本地产品地址或交付收据。已进入开发时附本轮需求、测试结果和检查点，方便下次继续。

## 完成条件

入组以环境验证、账号绑定、仓库写权限和两个权限视图均通过为准。查询以读到的状态为准。运行以健康检查为准。开发和交付以对应工作单、回归证据、缓冲站收据和远端状态为准。
