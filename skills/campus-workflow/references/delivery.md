# 交付与部署

## 提交说明

格式遵循 Conventional Commits，正文至少一条分点。功能用 feat，修复用 fix，重构用 refactor；fit 是拼写错误。

```text
fix(M02): 修复教室筛选条件丢失

- 切换日期时保留所选校区
- 补充筛选组合和空结果测试

Requirements: RES-01
```

submit 使用 --type、--summary、重复的 --detail 参数。脚本与缓冲站验证这些字段，正式 Gitee commit 和 GitHub 导出复用同一格式。不要将访问码、密码、日志或未验证声明写进描述。

## 双路交付

1. submit 校验白名单、来源、覆盖与证据，上传缓冲站。
2. 网站返回真实单号后，在独立目录从同一冻结基线应用同一差异；保留原工作树和 TDD 输入不变。
3. 自动提交到 GitHub development/<模块>/<成员>/<层>/<单号>，不强推、不合并 main。成员使用自己的真实仓库权限。
4. 缓冲站审核、独立 CI、正式提交和 Gitee 同步单独推进。普通状态按72小时，内存压力时只提前发布已通过项。
5. GitHub 推送失败保留缓冲单和导出目录；运行 python scripts/team.py github-retry --submission <原单号>；脚本读取缓冲站已收件的原补丁与描述重试，原工作区的新改动不会混入。导出目录已准备的提交会复用。

## 站点部署

目标服务器 119.3.126.218:22，站点 https://studyroom.seatraces.com。服务器凭据仅保存在私有配置或 GitHub Secrets，不写进 skill。

每个 GitHub 分支推送均需构建和测试。用户于2026-11-15授权 CI 通过后自动更新这个华为体验站，不再逐次请求上线确认；正式生产仍需人工审批。统一站点显示最近成功部署的分支快照，不自动合并成员分支。CI 验证可并行，部署与公开站点校验串行执行，落后的推送不得覆盖已经上线的更新版本。

部署包只含前端产物、两个 Java 服务及 SHA256 清单。服务器使用固定的 Compose 和接收器，不接收成员上传的任意命令、宿主挂载或生产配置。数据库持久化卷与应用发布目录分开，数据库备份不上传 GitHub。

健康检查覆盖首页、两个后端健康接口、登录配置和实际运行版本。`scripts/verify-deployment.py` 区分两种结果：`deployed` 仅在实际运行 SHA 与请求提交一致时代表本提交已上线；接收器返回 `skipped_old_push`，或校验时已运行更新发布序号的版本时，结果为 `superseded`。此时保留本次 CI 和接收器结果、请求与实际运行的 SHA/发布序号及替代证据，可结束本轮等待，但不能报告本提交已部署或上线通过。

失败尝试应用回退；数据库迁移和数据不会自动还原，不兼容迁移需人工处理。没有实际检查结果不得标记“已上线”。


本站已于2026-11-15通过公开HTTPS和真实浏览器注册、登录、退出、中英文切换验证。CI 文件为 .github/workflows/ci.yml，部署环境为 huawei-experience，启停开关为仓库变量 HUAWEI_SITE_READY。成员应从包含该 CI 文件的批准基线创建分支；旧分支必须先经协调流程取得更新后的基线。
