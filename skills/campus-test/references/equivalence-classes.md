# 等价类：每个场景要测哪几种数据情况和界面状态

建立检查方案时读本文件。等价类把一个场景可能遇到的数据切成有限几类，每类都要有明确结论：
测了，或写明为什么不测。划分由测试阶段做；**每个等价类怎样算对必须有原文依据，测试不新增预期**。
每个等价类编号写 `S01#2`（场景 S01 的第 2 个等价类）。

判据只有一句：**同一等价类里任取一个样本，结论相同**。两个样本可能得出不同结论，就拆成两类。

## 1. 以数据为主，少量界面状态

等价类主要切数据：数量、取值、数据源、初始状态。事实来源是 边界事实的数据边界
（可构造性、页容量、可空字段、数据源）和源码。
另外按 §2 末尾补少量**界面状态**：同样的数据，界面经过某个操作后结论可能不同，就单独切一类。

以下不按数据切，处理方式各不同：

- **入口**：一个场景就是一个原文场景章节，可能写了多个入口。`#1` 走原文的第一个（主）入口；
  其余每个入口切一类，等价类列写 `入口：从播放页进入`，常规数据，一律 UI 测试，怎样算对同 `#1`。
- **多个信息项 / 结果**：同一章节要求的多项内容（如显示标题和歌手、提示保存成功）都写进 `#1` 的“怎样算对”，
  不各切一类；只有某一项在不同数据下结论会变时，才按数据切。
- **界面呈现**（显示、持续、内容、变化）：不是一种情况，而是每个等价类“怎样算对”的写法，见 §3。

## 2. 怎么切

**常规情况（happy path）**：原文描述的典型数据，如多条、字段齐全。每个场景都有，固定为 `#1`。
没有数据变化的场景（纯静态页面、单一操作）可以只有这一个等价类。

**数量**：涉及列表、集合、分页、删除、刷新时切。

| 等价类 | 要回答什么 |
|---|---|
| 0 条 | 显示什么空态；有没有残留内容 |
| 1 条 | 正常显示；删掉它后进入空态而不是报错 |
| 多条 | 全部显示、顺序正确、无重复（常规情况通常就是这一类，不重复列） |
| 超过页容量 | 翻页 / 加载更多后结果完整、无重复、能到末页 |
| 末位操作 | 只剩 1 条时删除 / 取消 / 收藏后的状态 |

删除最后一条、刷新只剩一条、重复导入同一文件，是三类不同的末位问题，各切一类，不能互相替代。

**取值**：可为空的字段置空、超长 / 特殊字符。只在原文涉及输入或展示该字段时切。

**数据源一致性**：数据库 + 文件、缓存 + 服务等双源场景，按“只有 A / 只有 B / 对应 / 不对应”切，
不能只测“两边都有”。

**初始状态**：未登录 / 已登录、首次进入 / 有缓存再进入，原文涉及时切。

**界面状态**：常规数据下，界面经过一次操作后再看同一个结论。只在原文涉及该操作，
或原文的结论应该跨过这个操作仍然成立（如“一直显示”“保持选中”）时切。

| 等价类 | 要回答什么 | 何时切 |
|---|---|---|
| 离开再返回 | 跳到别的页面再返回，内容、选中、滚动位置是否保持或按原文刷新 | 原文结论在页面切换后仍要成立 |
| 切后台再回来 | 回到前台后显示与状态是否正确，播放 / 计时类是否继续 | 原文涉及播放、计时、持续显示 |
| 屏幕外的内容 | 滚动后才出现的项，内容和操作是否同样正确 | 列表超过一屏，原文结论涉及全部项 |
| 状态切换 | 播放 / 暂停、展开 / 收起、选中 / 取消来回切换后，显示是否跟着变 | 原文写了可切换的状态 |
| 重复操作 | 连点、重复进入同一页面，是否只生效一次、无重复内容 | 原文涉及提交、添加、收藏等写操作 |

界面状态类：

- 在“等价类”列写 `界面：离开再返回`，编号照常接在数据类后面；
- 怎样算对与 `#1` 相同（结论跨过该操作仍成立），原文另有写法的按原文；
- 一律用 UI 测试，从 `#1` 的初态出发，做完该操作再按 `#1` 的观察与比较判定；
- 每个场景通常 0–2 个，挑原文最相关的，不逐项铺满上表。

## 3. 每个等价类怎样算对

依据只能来自原文：

- 原文直接写了 → 依据写原文引用。
- 原文没写但另一处原文直接给出答案 → 逐字引用依据；不能凭实现或常识自定。
- 原文没写、且不同答案会改变结论（如 0 条时显示什么）→ 记入需求问题表（`Q`），
  按 [向人提问](../../campus-workflow/references/human-decision.md) 提问，该等价类保持待确认。
- 条件造不出来 → 先按 [检查方案](check-plan.md) 在授权隔离环境构造，造不出再问人；照样列出，状态写受阻，不能删掉。

**不能用当前实现的表现当某个等价类的“怎样算对”**——那是把现状当标准答案。

结论在界面上时，写清看什么、怎么判：

- 原文说“显示” → 核对实际可见与具体内容；要求持续显示时按原文时间关系采样，不自行新增持续时长。
- 原文写了“持续”“同步”“递增”这类时间关系 → 用关系式连续采样，不能用“存在”代替。
- 原文要求某个内容 → 核对具体值，不能降为“有这个控件”。例如要求标题 + 歌手，实际是标题 + 歌词，就是不满足。

## 4. 常见误用

- ❌ 把“多测几条数据”当等价类——同一等价类测十次仍是一类。
- ❌ 只测常规情况，用功能可用代替边界正确。
- ❌ 用“存在”代替“持续 / 递增 / 同步”——闪一帧和不动的进度都会漏掉。
- ❌ 某个等价类不好测就降低判据，或空着不写理由。
- ❌ 把上表界面状态逐项铺满——原文不涉及的操作不切。
- ❌ 把“显示 / 持续 / 内容”当界面状态切——那是怎样算对的写法。
