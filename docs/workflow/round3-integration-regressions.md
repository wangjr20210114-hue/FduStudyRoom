# 第二批集成回归

六名成员的后端收件补丁保持原样，协调修改另行提交。以下问题在协调环境中复现和修复，不代替成员原始证据或人工验收。

| 问题 | 实际验证 |
| --- | --- |
| 资格读取嵌套借用连接，单连接时返回503 | 相同HTTP测试先失败；绑定只读事务后相关11项通过；移除事务的独立变异再次失败。 |
| 资源拒绝审计丢失已认证操作人 | 补充操作人与服务端trace断言复现。外层记录拒绝、内层捕获可信操作人；同时保留错误服务键被安全链提前拒绝的审计。两项独立规则变异均检出。 |
| 截止后尚未落库的预约结果被统计忽略 | 2项断言先失败，修复后6项通过；单独暴露待处理和未确认计数，待处理时不显示最终签到/违约率，保留P08口径。独立变异检出2项失败。 |
| 旧验收评价缺少统一持久审计 | 2项HTTP/PG断言先失败、修复后通过；审计与评价原子提交，失败回滚，事件编号及trace稳定，不复制评价正文。移除入队的变异检出2项失败。 |
| 独立验收人看不到自己有权处理的待办 | 4项检查中2项先失败，修复后4项通过；仍需历史读取权限，只开放对应状态队列，不扩大普通用户历史范围。移除验收队列授权的变异检出。 |
| 资格接口接受中文部门代码，审计接口却拒绝 | 相同11项审计HTTP/PG测试先3项失败，修复后11项通过；仅对齐部门字段，长度、控制字符和其他状态字段规则仍保留，4项独立变异检出。 |
| 维修广播把个人预约请求发往流程服务 | 真实双服务确认维修已生效，而个人预约仍RESERVED。公开HTTP回归先1项失败、修正一处目标地址后同1项通过；独立副本恢复错地址再次触发相同目标失败，均无ERROR/SKIP。 |

维修广播的公共回归放在 `backend/workflow-service/src/test/java/com/campus/integration/RepairCrossServiceIntegrationTest.java`，位于六名成员可写目录之外。它启动两个真实JVM，通过公开HTTP准备账号、教室、座位、预约和报修，核对资源限制ACK、预约因维修终结、实际释放与不记违约；数据库仅作测试持久化观察，业务准备不跨模块写库。完整reactor、GitHub CI和缓冲站验证会自动发现该测试。

修复验证、整套回归、GitHub推送、CI、体验站版本以及本轮Gitee人工验收分别记录，不能混称全部完成。具体命令、原始失败、源文件快照和摘要保存在本机忽略目录，不提交日志、数据或凭据。
