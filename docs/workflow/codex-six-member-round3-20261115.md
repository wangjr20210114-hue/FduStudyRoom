## 真实界面联调

使用真实Chrome、两个Java服务、PostgreSQL、Mailpit和本机HTTPS代理。账号、教室、座位和业务单均由页面或公开API准备；没有通过跨模块写库造出业务成功状态。

- 注册后默认普通用户；管理员能修改资格和参数。导航保留同一页面文档，切换页面不触发整页刷新。
- 页面创建教室和座位、筛选插座、查询实际可预约结果、查看受权限保护的每日签到码。
- 整室申请经两名不同审批人同意后才落实占用；本人撤销后座位恢复。
- 报修经派单、维修、独立验收后恢复资源，真实评分和历史可见；参与维修的人即使有验收权限也不能验收自己的单。
- 同室两张维修单同时生效时，只解除一张仍受另一张限制；两张都解除后整室异常清除，但整室占用仍保留，须另行撤销整室申请才恢复座位。
- B页面座位链接进入C页面只做预填，明确点击确认才创建预约。上海次日07点正确对应UTC前一日23点；他人详情被拒绝，管理员使用授权列表快照。
- 取消释放时，只为选定预约注入一次传输503。页面显示待释放、已尝试1次及计划重试时间；后台到最早时间后用原内部编号和版本重试，真实资源服务确认后才显示释放完成、已尝试2次。同教室另一时段已落实的整室占用不受影响。
- 再次预约生成新记录和新操作编号，旧取消记录不复活。个人预约与保护整室单最后均由页面正常撤销，历史保留。
- 本人通知、真实已读时间、测试邮件状态、审计和统计均已联调；中文可读，英文切换可用。统计输入和设置历史在UTC浏览器中仍按上海时间处理。

D/E真实联调保存41个阶段记录、39张截图；C保存21个阶段记录、30张截图。阶段数包含登录、准备和观察，不等于需求数。原始驱动错误均保留并按原因纠正，不删失败后声称所有阶段一次通过。最终303项浏览器夹具回归另保存114张截图。
