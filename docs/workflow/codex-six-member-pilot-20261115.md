## 本轮发现并修复的问题

| 发现 | 修复 |
| --- | --- |
| WSL 工作区可能误用 Windows Docker CLI | 按工作区所属 WSL 发行版选引擎 |
| Maven 没有使用已预热的私有仓库 | 显式配置 MAVEN_ARGS 的 maven.repo.local |
| 只读源码挂载仍会暴露工作树私有文件 | 在成员容器中用只读空挂载遮罩 /workspace/.campus |
| 可信构建镜像缺少 unzip，Wrapper 退回另一种压缩包后校验失败 | 补齐 unzip，保留原下载校验和版本 |
| 只试部分场景时，原收据没有清楚区分完整需求 | 独立的 pilot 原文快照和收据；CLI 与服务端拒绝作为正式交付 |
| 被中断写入的缓存出现 0 字节，cp -Rn 会继续保留损坏文件 | 新增逐文件哈希校验和原子替换，已有正确缓存复用，损坏缓存从可信预热源修复；不删除额外缓存 |
| 新执行 helper 没有参与 workflow 版本校验 | 将 pilot.py 和 cache.py 纳入引擎指纹，变更后拒绝无确认恢复旧 workflow |
| 本地试跑缓冲服务和数据库曾意外退出 | 为本轮服务补上健康检查、重启策略和独立持久化卷；退出原因尚未证实，未认定是内存不足 |

曾遇到的编译入口、依赖损坏、PowerShell 参数拆分和断言摘要不精确均保留原始 ERROR，未当作有效 RED。PowerShell 运行 Maven 的 `-D...` 参数应加引号，或通过 argv 数组传入；成员源文件仍通过本人容器写入。

- 后续正式六人开发前，需将公共修复发布为共同冻结基线，再由该版本开启新 workflow。不能直接修改本轮冻结副本，继续冒用旧 workflow 的版本记录。
