# 首次构建的测试环境准备

`team.py build` 在 Maven 验证前启动当前工作区独立的 PostgreSQL 和测试邮箱，等待健康检查通过后传入测试环境变量。主应用、迁移探针和缓冲站测试使用各自测试库，不沿用应用业务库地址。端口自动分配且仅绑定本机。

验证结束或失败后，只释放本工作区的验证容器，保留测试卷和私有日志。应用配置与成员凭据不变。macOS/Linux 通过 `sh` 调用 Maven Wrapper，兼容检出后没有执行权限的脚本。

此次属于协调人公共基线修复，与成员业务补丁分别交付。修改 `tools/team/environment.py`、新增 `tests/team/test_build_readiness.py`，同步 `campus-build` 的 Stage 5、Stage 6 和阶段细则。未修改应用依赖、锁文件、成员已提交工作树或原始 TDD 输入。

## 验证

- 编排测试先失败、修复后 4/4 通过；包含失败释放、业务配置不变和脚本执行权限场景。
- 工具回归 139 项：137 通过，2 项因平台不适用跳过。

- 实际执行 `python scripts/team.py build --buffer`：缓冲站后端 33/33，前端 2 个测试文件、类型检查和构建通过。
- `campus-build` 技能格式验证通过；两次构建结束后验证容器已释放，数据卷保留。

上述实际构建在受信任的 Linux 协调验证环境运行。它不代表 Windows/macOS 新机器、缺工具自动安装或目标应用启动已验收。仅构建时没有启动目标应用。协调验证环境的 Docker 管理能力没有交给成员容器。

## 跨服务黑盒输入

本机构建、GitHub CI及缓冲站独立CI在主应用完整验证前，先对当前流程服务执行 `-pl workflow-service -am -DskipTests package`。身份模块可以通过该真实服务的公开HTTP接口验证鉴权，避免测试里递归执行Maven或引用其他领域的内部类。产物来自当前检出源，不提交JAR、缓存或测试凭据。缓冲站自身构建不增加这一步。
