# 六人入组与交付

## 组长分发

将桌面 FduStudyRoom-六人入组 中的六个 ZIP 分别私发给对应成员。每个 ZIP 中的 member.json 是该人的缓冲站凭据。访问码可以用于登录公网缓冲站。协调人保管其余五份及服务器运维资料。

需要重新生成时，在协调人项目的 IDE 对话中输入 `$campus-distribute 更新并检查六个成员包`。

| 个人包 | 模块 | 工作范围 |
| --- | --- | --- |
| a | M01 | 账号、角色与系统配置 |
| b | M02 | 自习室、座位与开放时段 |
| c | M03 | 个人预约、签到与违约 |
| d | M04 | 整教室申请与审批 |
| e | M05 | 报修、维修与验收 |
| f | M06 | 配套服务与统计 |

每个成员负责同一领域的前端和后端。用户名由成员填写，模块由个人包和服务器授权共同确定。

## 组员首次启动

1. 解压个人 ZIP，用已启用并登录 Codex 的 IDE 打开包含“先读我.txt”的文件夹。Windows 和 macOS 使用同一个入口。
2. 在 Codex 对话中输入 `$campus-join 帮我入组并继续我的未完成需求`。只想先搭环境时，输入 `$campus-join 帮我入组`。若 IDE 尚未列出技能，可以直接说“读取 .agents/skills/campus-join/SKILL.md，帮我入组”。
3. 在对话中确认本人的 GitHub 用户名，按浏览器或系统窗口提示完成首次授权。技能检查依赖和测试镜像，登记名额并接收此仓库的邀请。若系统要求重启，重启后打开同一目录，在对话中说 `$campus-join 继续入组`。
4. 准备通过后，技能在当前对话继续所选任务。下次可以直接打开它返回的项目目录（用户主目录下的 FduStudyRoom/代号），使用同一个技能。

| 在 IDE 对话中输入 | 结果 |
| --- | --- |
| `$campus-join 查看我的待办` | 显示本人模块前后端的需求和交付状态 |
| `$campus-join 启动本地产品` | 启动并验证应用，返回可打开的地址 |
| `$campus-join 继续我的未完成需求` | 恢复本模块工作单，执行 TDD、回归和交付 |
| `$campus-join 查看这次交付到哪了` | 核对缓冲站、GitHub、体验站和 Gitee 的实际进度 |

## 公网缓冲站与执行机

缓冲站入口为 https://gitbuffer.seatraces.com 。六份成员包使用冻结提交 2142af7a714377764fa32118fa99a92a8551a4d4。协调人查看全部记录，每位成员查看自己负责的模块。提交进入缓冲站后，同一差异推送 GitHub 开发分支。GitHub 的产品 CI 成功后触发华为体验站的现有部署流程。

Windows 任务 FduStudyRoom-TeamInvitations 核对入组登记。FduStudyRoom-TeamWorker 连接腾讯云缓冲站数据库并执行独立 CI 和 Gitee 分支发布。两项任务使用本机登录用户的会话。电脑关机、休眠或用户注销期间，公网照常收件。恢复登录、联网并启动 Docker 后，执行机继续处理符合条件的记录。

人工审核通过后，独立 CI 读取审核人、补丁和证据，在隔离容器验证。成功的提交每 72 小时发布到 Gitee 功能分支。腾讯云 RAM 使用率达到 85% 时按冷却间隔处理已通过的队首项。当前模式交付功能分支，合并由组长执行。缓冲站首页显示执行机连接状态，刷新可查看进展。

## 协调人维护

成员包生成器为 tools/onboarding/pack.py。输入为冻结提交的 Git bundle、协调人私有配置目录和输出目录。重新打包时复用 slots.local，保持已分发访问码有效。GitHub 账号首次登记后固定到本人的数字 ID。遇到人员交接，先核对现有记录，再人工调整绑定并轮换该人的访问码。

腾讯云端口 25534 仅监听回环地址。本机执行机通过 fdu-buffer-forward 的专用 SSH 密钥转发至本机回环 25535；数据库账号 fdu_buffer_worker 可以读取证据并推进已审核状态。业务提交、审核人和补丁保留原值。执行机私钥、数据库密码和协调人访问码保存在 Windows 用户自己的 LocalAppData/FduStudyRoom/team-onboarding-20261119 目录。

服务器升级程序为 tools/onboarding/upgrade_buffer.py、connect_worker.py 和 dashboard_update.py。部署文件及已有私有配置的备份保存在 /opt/fdu-gitbuffer-preview-20261113。迁移历史使用 history.py，目标有记录且摘要不一致时会停止。安装脚本和验证程序属于协调人基线变更。

## 已验证的范围

成员技能入口已用六份个人包分别解压、检出和复用同一工程。每份包均通过项目内技能一致性检查，在独立缓冲站读取了本人前后端的需求，共 12 个视图。自动化用例还覆盖账号不符、等待仓库邀请、重复入组，以及从已入组项目再次打开技能。入组测试使用隔离数据，真实账号由成员首次使用时自行登记。

2026-11-19 在独立 PostgreSQL 中用六个 ZIP 分别检出和重复打开同一冻结版本，安装并核对五个技能，验证 12 个权限视图，并检查重复登记、账号冲突和成员访问名册的权限。公网另外逐一核对了六个成员的两个视图。迁入 22 条历史变更和 41 条既有操作记录。执行机完成了 6 条已审核记录的分支投递，六个远端提交号均逐条相符。另在独立目录重新执行了 M01 的一次 CI，核对补丁并通过了真实容器回归。

当前测试机为 Windows，使用 WSL 的 Linux 容器。全新 Windows 和实体 macOS 的安装许可、虚拟化及各组员首次账号登录，仍需在对应设备上完成。
